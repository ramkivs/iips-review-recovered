# PROGRAM v3.0 — Phase 13.3: Platform Operations Authority & Security Map

Maps the authority/security boundary for any future read-only Platform Operations surface.
**Inspection only — no implementation.**

## Authority chain (frozen G3)
```
Keycloak (WHO) → OIDC/JWKS → ValidatedIdentity → EnterpriseRuntime.Principal
  → SecuredExecutor.authenticate (401)
  → SecuredExecutor.authorize (EnterpriseRuntime RBAC + gate) (403)
  → server-side tenant validation
  → governed audit (allow/deny)
  → governed v2.0 contract (CloudHaRuntime / DR / V2Observability / PerformanceScaling / ...)
  → read-only DTO
  → React (presentation only)
```

## Key finding
The Platform Operations read endpoints are **already enforced through this chain** in Phase 12.1
(`/api/admin/platform` etc., `guardAdmin`). No new authority is needed to read them.

## Security properties

| Property | Rule |
|---|---|
| Authentication | Keycloak only — no self-issued JWT / localStorage / custom password |
| Authorization | `EnterpriseRuntime` RBAC + gate — no second RBAC, no frontend role checks as security |
| Tenant | platform-validated server-side; never from URL/query/localStorage/header/React state |
| Audit | `EnterpriseRuntime.auditLog` — no second audit system |
| Frontend | NOT an authority; visibility ≠ authorization |
| 401 / 403 | missing/invalid → 401; unauthorized → 403 |

## Read-only boundary (critical)
- **READ:** health, DR status, telemetry, performance, migration history, workflow version,
  marketplace list.
- **MUTATION (NOT exposed):** `markDown`, `rollingRestart`, `register`, `place`, `restore`,
  `clear`, `recordMigration`, `define`, `execute`, `register/revoke/certify` — all PLATFORM-ONLY.
- **No lifecycle control, no restart, no restore, no activation** in a read surface.

## Prohibited (never)
localStorage auth · client tenant · frontend RBAC · ad-hoc JWT · second audit/permission system ·
fabricated health/status/SLO/capacity.

## Conclusion
A read-only Platform Operations surface is **safe** (governed reads, G3-enforced, already exposed
admin-side). It adds **no new governed capability**; any Phase 13.4 UI would re-present existing
admin reads or expose them to additional roles — a product/IA decision, not a security gap.
