# PROGRAM v3.0 — Phase 13.3: Platform Operations Gap Analysis

Gap classification: **G1** UI gap · **G2** transport gap · **G3** platform contract gap ·
**G4** governance/security gap (HARD STOP) · **G5** data-source gap.

| Desired | Actual | Class | Action |
|---|---|---|---|
| Platform Ops read UI (health/DR/telemetry/perf) | already exposed in admin (admin-gated) | **G1** (UI placement) | Product/IA decision, not a governed-contract gap |
| Non-admin read of Platform Ops | currently admin-only | **G1/G2** (authz scope) | Optional; requires role decision (viewer/analyst read of operational state) |
| Uptime % / health score / SLO | ❌ no governed source | **G3** (platform) | UNAVAILABLE — never fabricate |
| Capacity / entitlement | ❌ no store | **G3** | UNAVAILABLE |
| DR restore / restart / activation UI | ❌ mutation (platform-only) | **G3** | OUT of scope (PLATFORM-ONLY) |
| Regional/site status granularity | ⚠️ `region` in DR/GovernedData | **G1** | partial |

## Classification summary
- **G1:** 1–2 (UI placement of existing admin reads; optional non-admin role scope).
- **G2:** 0 (transport already exists).
- **G3:** 2 (uptime/SLO, capacity) + lifecycle mutations (platform-only, out of scope).
- **G4:** **0 — no HARD STOP.**
- **G5:** 0.

## Key conclusion
**G4 = 0**; no governance/security HARD STOP. All Platform Operations **read** capabilities are
genuinely governed and **already exposed** (admin, G3-enforced). The only Phase 13.4 decision is
**IA placement / role visibility**, not a governed-contract gap. Lifecycle mutations and fabricated
SLO/capacity metrics must remain UNAVAILABLE.
