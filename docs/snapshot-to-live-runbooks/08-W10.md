# Runbook 08 — Sequence 7: W10 issuer-to-engine input mapping and qualification

**Script:** `07-w10-mapping-qualify.ps1`

## 1. Objective
Verify issuer-specific engine-input mapping and source/period qualification evidence: the
pinned platform W10 suites plus the served investment-coverage report plus at most one
identity-qualify call for the resolved issuer. Records whether W11 has a sufficiently
qualified issuer — today: **NO** (53 of 115 required inputs authorised; 62 withheld;
`QUALIFICATION_NOT_QUALIFIED` is the designed behaviour, §16.327 §4).

## 2. Repository locations
IRR: routes `GET /api/investment/coverage/investment?asOf=` (investment report),
`GET /api/investment/coverage?asOf=` (identities coverage — authoritative per-issuer
isin/exchange/symbol), `POST /api/dhan/identity/qualify` (body = `isin`/`exchange`/`symbol`
only, per `validateDhanIdentityRequest` in `frontend/server/market-data/dhanIdentityTransport.ts`).
The captured identities response uses LITERAL DOTTED property names: match the item on
`raw['securityIdentity.securityId']`, read ISIN from `raw['securityIdentity.isin']`, symbol from
`raw.symbol`, and resolve the exchange from `binding.listingId` via the canonical listing-ID
contract (`parseListingId` in `iips-platform/src/investment/contracts/ids.ts`:
`IN:<EXCHANGE>:<SYMBOL>:<SERIES>:<INSTRUMENT>`, closed vocabularies — never guessed or blindly
split). Captured INFY row (STL-07-W10-20261126T105422Z): securityId `ISIN:INE009A01021:EQ`,
isin `INE009A01021`, symbol `INFY`, listingId `IN:NSE:INFY:EQ:EQUITY` → exchange `NSE`.
platform suites `iips-platform/tests/investment/w10IssuerEngineMapping.test.ts`,
`w10IssuerEngineQualification.test.ts`; W10 records `docs/integration/W10-*-2026-11-12.md`.

## 8. Execution procedure
```powershell
powershell.exe -NoExit -ExecutionPolicy Bypass -File .\07-w10-mapping-qualify.ps1 -AsOf 2026-11-24
```
(a) `npx tsx --test tests/investment/w10IssuerEngineMapping.test.ts tests/investment/w10IssuerEngineQualification.test.ts`
in `iips-platform/`; (b) capture the investment-coverage route verbatim; (c) the optional
`POST /api/dhan/identity/qualify` for the resolved securityId is issued ONLY when all gates pass
(suites exit 0 AND investment-coverage route HTTP 200 AND daemon 8791 reachable AND the issuer
isin/exchange/symbol were found in the identities coverage response) — otherwise the leg is
recorded as NOT EXECUTED with the actual reason and no POST is issued; when issued the body is
`{"isin":…,"exchange":…,"symbol":…}` read from the matching identities-route row
(`raw['securityIdentity.isin']`, `raw.symbol`, and the exchange resolved from
`binding.listingId` through the canonical listing-ID parser; all three validated — ISIN grammar
cross-checked against the securityId ISIN segment, exchange NSE/BSE, symbol grammar — before the
POST is permitted; never a securityId field, never derived by parsing the securityId string),
it is a single attempt with no retry, the response body is preserved
verbatim, the actual HTTP status is recorded, and the call counts as successful ONLY on a 2xx
status (non-2xx = captured but not successful, never inferred from body or attempt);
(d) write `w10-qualification-summary.json`
(53/115 census of record + sufficiency verdict + qualifyCallMade/qualifyHttpStatus/
qualifyResponseCaptured/qualifySucceeded/qualifySkipReason).

## 11. Evidence capture

## 12. Evidence validation
`checks.json`; manifest verify.

## 13. Result classification
PASS = suites pass + evidence captured and every REQUIRED check Ok (the *sufficiency* verdict
is recorded, possibly negative); BLOCKED = API down; FAIL = suite failure. Only `optional-leg-*`
bookkeeping checks (daemon probe, issuer values, not-executed reason) are excluded from the PASS
aggregation — once the qualify POST has been attempted, `identity-qualify-succeeded` (2xx only)
is a REQUIRED check, so a non-2xx response (e.g. HTTP 400 INVALID_REQUEST) makes Result=PASS
impossible (2026-11-26 fix for STL-07-W10-20261126T082732Z, which reported PASS with
failedCheckCount=1). The response is still captured verbatim with its actual status.

## 14. Downstream impact (per the brief's Example 2)
If a sufficiently qualified issuer were established, step 09 (W11) would execute against it.
Since qualification is insufficient (62 inputs unauthorised — a methodology/source decision),
**W11 actual execution cannot proceed**; step 09 records the verbatim refusal instead. W11
remains blocked until W10 authorisation improves (plus W03/B02 and W04's 1/64 bound).

## 15. Unsuccessful / unavailable evidence
- Daemon absent (8791 closed) → qualify leg NOT EXECUTED (reason recorded; no POST issued);
  mapping evidence still collected from suites + route. Resume = daemon on 8791 only — the
  runtime environment is established by the startup process, no env-file check applies.
- Suites not exit 0 or route non-200 → qualify POST not issued (gate failed, reason recorded);
  suite failure additionally makes W10 FAIL.
- Qualify POST executed but non-2xx → response preserved verbatim, actual status recorded,
  `qualifySucceeded=false`; W10 PASS unaffected (optional leg), the negative outcome is evidence.
- Suite failure → FAIL; the failing vector names the mapping defect.
- Existing evidence reusable: the 53/115 census of record and prior route captures verify
  against the manifest; a new capture is required only when the revision or asOf changed.
