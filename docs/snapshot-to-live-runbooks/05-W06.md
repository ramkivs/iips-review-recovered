# Runbook 05 — Sequence 4: W06 actual quote availability and freshness per holding

**Script:** `04-w06-quote-freshness-measure.ps1`

## 1. Objective
Measure ACTUAL per-holding quote availability and freshness for the captured revision
(`DHAN_PORTFOLIO` rev as captured) — W06 decision-B re-assessment input. W04 bounds the
numerator: only resolved identities (today ≤ 1/64) get any data call.

## 2. Repository locations
IRR API routes: `POST /api/dhan/quotes` `{companyId, securityId, exchangeSegment}` and
`GET /api/dhan/freshness?domain=D01_QUOTES&companyId=..&exchangeSegment=..&securityId=..`
(served through `quoteConsumptionBoundary.ts` — the ONE server-side quote consumer, W-29).
Identities from `GET /api/investment/coverage?asOf=<date>`. IPD daemon on `127.0.0.1:8791`.

## 3. Input identification
Step-02/03 capture + identities route; `-AsOf` date; the three market-data settings
(`IIPS_MARKET_DATA_TRANSPORT_URL`, `IIPS_MARKET_DATA_BASE_URL`, `IIPS_MARKET_DATA_TRANSPORT_TOKEN`)
supplied by the **existing managed startup environment** — the process environment of the
startup-loaded operator window. The script reads the process environment only and never inspects
`.env.local` (no duplicate entries required there). The token is a server-side value, never
printed, logged or on a command line — only a missing NAME is ever reported.

## 4. Prerequisites
00-preflight PASS; daemon listening on 8791; the three market-data settings present AND non-empty
in the managed startup environment (startup-loaded operator window); API healthy. The script is
run in that same startup-loaded window.
Quote/history requests are NOT used as a configuration dry-run (OPERATOR_RUNBOOK §3.3a); the
only quote consumption is the bounded per-identity measurement below.

## 5. Runtime requirements
IRR API (:8787) + IPD market-data daemon (:8791). No UI.

## 6. Startup instructions
Services via the existing IIPS managed startup script (which establishes the managed startup
environment — including the three `IIPS_MARKET_DATA_*` settings — in the operator window).
Daemon: in `H:\IIPS\iips-production-market-data` run `npm run start:market-data-daemon`
(loopback only, no arguments, existing approved host configuration; do not create/repair
credential material). API: `npm run server:dev` in `frontend/`. Run the W06 script itself in the
startup-loaded operator window.

## 7. Basic checks
`/api/health` 200; `GET /api/dhan/health` 200 (transport reachability only — NOT live-vendor
proof, and not a quote request); TCP 8791 open; the three market-data settings present and
non-empty in the managed startup environment (process env — names only, values never read into
output).

## 8. Execution procedure
```powershell
powershell.exe -NoExit -ExecutionPolicy Bypass -File .\04-w06-quote-freshness-measure.ps1 -AsOf 2026-11-24
```
For every census row: no stored `securityId` → record `IDENTITY_UNRESOLVED`, **zero calls**;
stored `ISIN:…:…` → exactly **one** POST quotes + **one** GET freshness, bodies saved verbatim
under `output/observations/<rowId>/`; verdict mapped to the W06 vocabulary
(GOOD→COVERAGE_CURRENT, STALE→COVERAGE_STALE, UNAVAILABLE→COVERAGE_UNAVAILABLE,
UNKNOWN→COVERAGE_UNKNOWN — UNKNOWN is "no observation", distinct from STALE). No retry/refresh.

## 9. Scripts / invocation
`04-w06-quote-freshness-measure.ps1 [-AsOf <date>] [-TimeoutSeconds 300]`.

## 10. Expected output
`w06-observation-summary.json`: rows, per-row category, `totalDataCalls = 2 × resolved`.
Verdicts may honestly be STALE/UNAVAILABLE/UNKNOWN — that is a PASS of *measurement*.

## 11. Evidence capture
`04-W06/<id>/output/observations/...` + `identities-route-response.json` + summary. These
observations feed step 08 (`--observations-dir`).

## 12. Evidence validation
`boundary-respected` check (calls == 2×resolved); manifest verify.

## 13. Result classification
PASS = measurement completed within the boundary; BLOCKED = daemon/env/route unavailable;
FAIL = boundary violation or missing evidence.

## 14. Downstream impact
PASS feeds **W12 methodology evaluation** (actual observations for D1–D3/θM) and **W13 actual
valuation** (step 8 injects these responses as readers). W06 acceptance itself remains an owner
decision (decision B, §16.321/§16.322) — this package is its input.

## 15. Unsuccessful / unavailable evidence
- Daemon down / market-data settings missing-or-blank in the managed startup environment →
  BLOCKED with resume requirement (daemon on 8791 + the three `IIPS_MARKET_DATA_*` settings
  present-and-nonempty in the startup-loaded window — NOT in `.env.local` — + API restart).
  W13 actual valuation then stays blocked; step 08 reports BLOCKED for missing observations.
  Independent continuations: steps 05/07/10/11 API+offline legs.
- A quote call returning an error body → recorded verbatim as `OBSERVATION_UNREADABLE`-class
  input (no retry); the measurement still PASSes if the call accounting is right — the *verdict*
  is what W06 measures.
- New capture required only if step 02/03 found no consistent capture; otherwise existing
  observations can be re-verified from the saved responses.
