# Runbook 03 — Sequence 2: W03 actual revision/report inventory reconciliation

**Script:** `02-w03-inventory-reconcile.ps1`

## 1. Objective
Reconcile the actual portfolio/report inventory against the captured portfolio revision —
roadmap W03 acceptance: "counts reconcile to captured revision, empty/unavailable/unknown
distinguished".

## 2. Repository locations
IRR: capture CLI `frontend/server/user-portfolio/capture/`; API routes `/api/user-portfolios`,
`/api/user-portfolios/:id`, `/:id/revisions`, `/:id/holdings`, `/api/reports/context`,
`/api/reports/artifacts` (served by the API transport process, `executive-transport.ts`).
IPD: G3 IPC provider owns the store (`C:\iips-data\iips\user-portfolio.sqlite`); IRR never opens it.

## 3. Input identification
Newest `CONSISTENT_CAPTURE` summary under the evidence root or `%LOCALAPPDATA%\IIPS\w11-dep1-capture`
(reused — no new capture needed); otherwise a fresh read-only capture into this package
(`--portfolio-id DHAN_PORTFOLIO`). Reports env names for the artifacts leg.

## 4. Prerequisites
00-preflight PASS; IRR API healthy on :8787; G3 pipe present if a fresh capture is needed;
`IIPS_REPORTS_OWNER_PATH` + `IIPS_NP04_DATABASE_PATH` for the reports leg (optional — skipped as
a recorded BLOCKED leg otherwise).

## 5. Runtime requirements
IRR API (:8787) always; IPD G3 provider for a fresh capture; reports leg needs the NP-04 store
provisioned (a read can no longer create it — G-11 hardening, OPERATOR_RUNBOOK §3.2).

## 6. Startup instructions
Per `01-PREFLIGHT.md` §6 (API always; provider when capturing).

## 7. Basic checks
`GET /api/health` → 200; pipe probe; capture exit 0 when run.

## 8. Execution procedure
```powershell
powershell.exe -NoExit -ExecutionPolicy Bypass -File .\02-w03-inventory-reconcile.ps1
```
Steps inside: obtain/reuse capture → capture API list/detail/revisions/holdings verbatim →
reconcile revision, holdings count, single history entry at that revision → reports context +
artifacts count (separate number, never mixed with holdings) → write `reconciliation.json`.

## 9. Scripts / invocation
`02-w03-inventory-reconcile.ps1 [-PortfolioId DHAN_PORTFOLIO] [-TimeoutSeconds 180]`.

## 10. Expected output
`reconciliation.json` with capture vs API revision/holdings equality; `RESULT [PASS] ...`.

## 11. Evidence capture
Package `02-W03/<id>/output/`: `capture-summary.json`, `api-user-portfolios-*.json`,
`api-reports-*.json`, `reconciliation.json`, capture run log if fresh.

## 12. Evidence validation
`checks.json` reconcile-* ids all PASS; manifest verify.

## 13. Result classification
PASS = counts reconcile; BLOCKED = no capture obtainable (exit 10/11) or API down; FAIL = any
mismatch (e.g. holdings count differs from captured `holdingsCount` — investigate).

## 14. Downstream impact
PASS unblocks **W05, W06, W09 actual-data verification** (steps 05/04/06) — they consume this
capture ref. Example per the brief: with the inventory reconciled, steps 04 (W06 measurement),
05 (W05 coverage), 06 (W09 read path) proceed; without the captured revision they remain BLOCKED
on B02 and only synthetic/offline steps can run.

## 15. Unsuccessful / unavailable evidence
- Captured revision cannot be supplied (provider down, binding refused, B02 absent) → BLOCKED;
  missing input = the bound IPD G3 provider / an authorized host capture; steps 04/05/06 stay
  BLOCKED; independent steps that can continue: 01 (if a prior capture exists), 07–12 offline
  legs that reuse existing packages. Resume evidence = a fresh `CONSISTENT_CAPTURE` summary
  whose revision reconciles.
- Reports leg skipped → recorded as BLOCKED leg (DISTINCT from empty: a 200-empty artifacts list
  is a successful empty answer; 503 persistence-unavailable is an unavailable state).
