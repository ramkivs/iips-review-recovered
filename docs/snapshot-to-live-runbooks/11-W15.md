**Script:** `10-w15-disposition-readback.ps1`

## 1. Objective
Verify portfolio-linked disposition and owner-scoped readback: a recording disposition run for
the covered holding, an identical repeat proving the content-identical non-write (UNCHANGED),
plus API dispositions/reports readback and chain readback (IID Stage 6 pattern, §16.319/§16.320).

## 2. Repository locations
IRR: `frontend/server/investment/cli/generate-holding-disposition.ts`,
`frontend/server/investment/cli/show-investment-chain.ts`; routes
`/api/investment/portfolio/:id/dispositions`, `/api/investment/portfolio/:id/holding/:securityId`,
`/api/reports/artifacts`; NP-04/NP-06 chains in `frontend/server/reports/` + `investment/change/`.

## 3. Input identification
`-PortfolioId DHAN_PORTFOLIO`, `-HoldingRef symbol:INFY`, `-IssuerId IN:CIN:L85110KA1981PLC013115`
(governed issuer for the chain readback; the persisted chain scope is
`co:IN:CIN:L85110KA1981PLC013115`, not derived from the holding selector). The runtime values
`IIPS_NP04_DATABASE_PATH` (NP-04 store, provisioned per G-11: reads never create it),
`IIPS_REPORTS_OWNER_PATH` (reports-owner carrier file — byte-exact pinned SHA-256) and
`IIPS_DATA_DIR` (data root feeding identity sources + the governed limits policy, Stage 6
S6-1: `limits-policy/2026-11`) are set IN-WINDOW by the AUTHORITATIVE SERVER STARTUP BLOCK in
the startup-loaded operator window and are also supplied to the managed daemon. The W15
script never inspects the env file and never presence-checks individual variables; reports
readiness is the actual `GET /api/reports/context` → 200. The script forwards `--db` /
`--owner-carrier` / `--data-root` to the disposition CLI (and `--db` / `--owner-carrier` to the
chain CLI — that parser has no `--data-root`) ONLY when the corresponding `$env:` value is
non-empty, never as empty strings; CLI children otherwise inherit the operator process
environment unchanged. `IIPS_OWNER_CONTEXT_PATH` is never used here — it is not
interchangeable with `IIPS_REPORTS_OWNER_PATH`.

write is a defect).

report artifacts for **W16** (step 11).

## 15. Unsuccessful / unavailable evidence
- Reports context non-200 (e.g. 503 persistence-unavailable = NP-04 store not provisioned) →
  BLOCKED (resume: ensure the startup script supplied the reports settings and the store is
  provisioned; do NOT point the read at a substitute store — fail-closed 503 is the designed
  answer). Independent legs (steps 01–09, 11 offline) continue.
- Existing evidence reusable: prior disposition chains and artifacts verify via manifest +
  digests; a new recording run is required only to demonstrate a fresh disposition, and the
  identical-repeat UNCHANGED is itself the regression evidence.
