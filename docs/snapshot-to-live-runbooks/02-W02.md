# Runbook 02 — Sequence 1: W02 concurrency, cross-call consistency, revision-change, multi-process coherence

**Script:** `01-w02-concurrency-verify.ps1`

## 1. Objective
Technical verification that concurrent/cross-call reads of the actual persisted portfolio are
consistent and revision-stable, and that IPD's read-snapshot race suites pass on the host IPD
checkout (revision-change behaviour).

## 2. Repository locations
IRR: `frontend/server/user-portfolio/capture/capture-owner-bound-portfolio.ts` (read-only
capture CLI: list → get → revisions → get, whole-attempt discard on mismatch). IPD:
`tests/stage2_portfolio_read_snapshot.test.ts` (11 two-connection barrier cases),
`tests/g3_portfolio_read_isolation.test.ts` (owner isolation) in `H:\IIPS\iips-production-market-data`.

## 3. Input identification
Environment names `IIPS_G2_IPC_ENDPOINT`, `IIPS_G3_IPC_BINDING_PROVISIONED` loaded in the
script window (see README loader); running IPD G3 provider on `\\.\pipe\iips-user-portfolio-v1`;
`frontend\node_modules` installed.

## 4. Prerequisites
00-preflight PASS; IPD G3 IPC provider running and bound (one ACTIVE S1 binding verified by IPD
per request).

## 5. Runtime requirements
IPD G3 IPC provider only. The IRR API is not required for this step.

## 6. Startup instructions
Provider start per `01-PREFLIGHT.md` §6. The script starts nothing.

## 7. Basic checks
Pipe present (`[IO.Directory]::GetFiles('\\.\pipe\')` contains the name), ≥1
`ipc\entrypoint.js` process, env names defined, `frontend\node_modules` present.

## 8. Execution procedure
```powershell
cd C:\tmp\iips-review-recovered\tools\windows\snapshot-to-live
powershell.exe -NoExit -ExecutionPolicy Bypass -File .\01-w02-concurrency-verify.ps1
```
The script (a) runs the capture CLI twice into separate output roots via **verified
`node.exe` + `npx-cli.js`** (`Invoke-StlNpx`; the `npx.ps1` wrapper is never launched), then
(b) launches `-ConcurrentCaptures` (default 2) captures simultaneously as separate processes
(`Start-StlNativeProcess` with centrally quoted arguments) and compares revision + digest
**by equality only** (values never recorded), then (c) runs the two IPD test suites with the
correct build layout: `outDir` is read from the IPD `tsconfig.json` (normally `dist`);
compiled tests run as `node.exe --test dist\tests\<name>.test.js` only when the compiled
output is fresh (newest `src`/`tests` mtime ≤ compiled mtime); otherwise a **targeted**
`npm run build` runs first (never a full regression suite; generated `.js` is never copied
into `src`), with a `tsx --test tests\...` source-run fallback if the build cannot produce
the compiled tests. The mode used is recorded in `checks.json` (`ipd-test-mode`).

## 9. Scripts / invocation
`01-w02-concurrency-verify.ps1 [-ConcurrentCaptures 2] [-TimeoutSeconds 300]`.

## 10. Expected output
Both concurrent captures exit 0 (`CONSISTENT_CAPTURE`), same revision and digest; IPD suites
exit 0 in the recorded mode (`compiled-dist` preferred, `tsx-source-fallback` recorded).
Logs under `output\concurrent-*.log`, `output\ipd-*.log`, `output\ipd-build.log`;
checks `node-exe-verified`, `npx-cli-located`, `ipd-build-outdir`, `ipd-targeted-build`,
`ipd-test-mode`.

## 11. Evidence capture
`G:\IIPS-Evidence\snapshot-to-live\01-W02\<id>\` (capture summaries under `output\capture-*/`,
`output\concurrent-*/SANITIZED-SUMMARY\`, suite logs), sealed manifest.

## 12. Evidence validation
Manifest verify + manual: `checks.json` `concurrent-captures-consistent`, `ipd-suite-pass-*`.

## 13. Result classification
PASS = all of the above; BLOCKED = pipe/env/deps missing; FAIL = any inconsistency or suite
failure (an INCONSISTENT_READ exit 13 from the capture CLI is recorded and classified FAIL —
investigate, never re-labelled).

## 14. Downstream impact
PASS strengthens W09 (step 6) revision-aware read-path verification. W02's own acceptance
additionally needs the IPD-side suites green on the pinned IPD main and the IRR package pin
advanced to a main containing IPD #150 (`0b6a0bea`, verified live ancestor of IPD `84e988b`,
tracker §16.325) — the pin advance is a separate work item, not done by this script.

## 15. Unsuccessful / unavailable evidence
- Provider down / binding refused (capture exit 10/11) → BLOCKED; resume = start provider with
  an active owner binding; a *new capture* is then required (existing summaries cannot prove
  current coherence).
- IPD suites fail → FAIL; the failing case names the race/isolation defect; W09 actual-data
  acceptance stays blocked until fixed on the IPD side (IPD-owned).
- No write is ever issued from IRR for revision-change testing (W-1 default-deny); revision
  change is covered by IPD's fixture suites only.
