# Runbook 06 — Sequence 5: W05 actual financial coverage and source/rights evidence

**Script:** `05-w05-financial-coverage.ps1` (drives the existing validated W05 host procedure)

## 1. Objective
Establish actual issuer-level financial coverage and source/rights evidence over the captured
revision, via the validated W05 host procedure — input to W10 mapping, W11 prerequisites and
W12 methodology evaluation. (W05 workstream status stays IN PROGRESS — NOT ACCEPTED per
tracker §16.288–§16.292 regardless of this package.)

## 2. Repository locations
IRR: `tools/windows/W05-STEP1..4*.ps1` + `W05-SCRIPT-HELPERS.psm1`;
`docs/integration/W05-SCRIPTED-EXECUTION-RUNBOOK-2026-11-18.md` (canonical invocation chain);
routes `GET /api/investment/coverage?asOf=`, `GET /api/investment/coverage/investment?asOf=`;
platform suites `iips-platform/tests/investment/w05*.test.ts`.

## 3. Input identification
Step-02 capture (revision-1 census, 64 rows); `-AsOf` date; `-PortfolioId DHAN_PORTFOLIO`.

## 4. Prerequisites
00-preflight PASS; IRR API healthy; step-02 package present.

## 5. Runtime requirements
IRR API only. The platform suites run offline in `iips-platform/`.

## 6. Startup instructions
API per `01-PREFLIGHT.md` §6.

## 7. Basic checks
`/api/health` 200; the four W05 step scripts present with the parameter names used by the
driver (RepoRoot/BaseUrl/AsOf/OutDir; BundleDir; ExpectedRows; BaseUrl/AsOf/OutDir).

## 8. Execution procedure
```powershell
powershell.exe -NoExit -ExecutionPolicy Bypass -File .\05-w05-financial-coverage.ps1 -AsOf 2026-11-24
```
Canonical chain (per the W05 runbook): STEP1 capture identities route → STEP2 reconciliation
from the bundle → STEP3 independent verification of the reconciliation → STEP4 host coverage
routes (per-route report contracts; a 503 is never a report capture) → plus this driver's
`investment-coverage-route.json` capture and the w05 platform source/rights suites.

## 9. Scripts / invocation
`05-w05-financial-coverage.ps1 [-AsOf <date>] [-TimeoutSeconds 600]`.

## 10. Expected output
Four step results PASS under `output/w05/step1-bundle|step2-reconciliation|step3|step4-*`,
`investment-coverage-route.json` (200, InvestmentCoverageReport shape), platform log exit 0.

## 11. Evidence capture
`05-W05/<id>/output/w05/...` + route captures; sealed manifest.

## 12. Evidence validation
Each step script's own result object is preserved; `checks.json` aggregates all four
`W05-STEPn-pass` ids + route + platform suite.

## 13. Result classification
PASS = all four steps PASS + route 200 + suites exit 0; BLOCKED = API down; FAIL otherwise.

## 14. Downstream impact
PASS supplies **W10 issuer-mapping inputs**, **W11 execution prerequisites**, and the
**W05/W06 actual evidence** that W12 D1–D3/θM final decisions wait on.

## 15. Unsuccessful / unavailable evidence
- API down → BLOCKED (resume: `npm run server:dev`). Missing step scripts or changed parameter
  names → FAIL with the exact missing name (fix the driver's step table, never the W05
  scripts' contract). A 503 on a coverage route is recorded as unavailable (never an empty
  report); the step FAILs its shape check only if the route is expected to serve.
- Eligible-set/census mismatches inside STEP2/3 are FAILs of the evidence, preserved verbatim;
  resume requires the reconciled bundle, not a re-capture, unless the revision changed.
