## Why no denominator exists in this environment

The existing G-2 path is `frontend/server/user-portfolio/ipcPortAdapter.ts`, with `IpcUserPortfolioPort.listPortfolios`, `getPortfolio` and `revisionHistory`. The existing read-only capture in `frontend/server/user-portfolio/capture/` makes a consistent list/get/revisions/get capture and retains wire identity locally. Its supported operator environment is the already-running, owner-bound Windows IPC service; see `docs/integration/W11-DEP1-OWNER-BOUND-PORTFOLIO-CAPTURE-UTILITY-2026-11-13.md`. The capture selects one portfolio at a time when more than one is listed; complete W-28 coverage requires consistent inclusion of all active portfolios, not merely the selected one.

In this Linux sandbox both the G-2 endpoint and binding-precondition environment settings were absent, as were the root and frontend `.env.local` configuration files. No repository-local IPC socket or portfolio database was found in the inspected locations. The Windows host and its owner-bound service are not available here. Neither the existence of a store nor an empty portfolio can be inferred from that absence. No owner-bound read, local Windows synchronization, service start or database access was attempted.
