## Trace and limitations

The Vite `/api` proxy targets the local executive transport, whose dispatcher routes coverage, change, assessment and disposition requests (`frontend/vite.config.ts`, `frontend/server/executive-transport.ts`). Investment clients use relative URLs. The product UI formats persisted values (including derived numbers already computed by the backend), it does not calculate financial valuations; component tests use synthetic JSON fixtures and are not proof of an actual backend exchange. Evidence and rationale are taken from their respective stored payloads; labels and missing-state copy are UI text. Sector reference is separately disclosed, not issuer-specific evidence. Backend identity and dataset source handling lives in `iips-platform/src/investment/identity` and `ingestion`; synthetic M1 uses `demo/m1Pipeline.ts` and fixture datasets, not issuer evidence. Real-issuer evidence bundles show operator-side assessments, not this complete UI journey.

The holding link carries `portfolioId` and `securityId` into the company URL; the timeline is on the same page, so those query parameters remain there. The assessment version selector is component state, not a durable/shareable URL, and selecting a historical version does not select a matching disposition. The new alert compares the displayed issuer and report ID to the disposition's cited issuer and report ID; it does not create or infer a new disposition. Candidate navigation now accurately says it opens the current assessment, which may not be the cited version. Assessment comparisons on the company endpoint do not establish a UI path for historical disposition comparison, even though backend comparison grammar has disposition tests. A portfolio row can lack a company link when disposition list data does not provide issuer identity. Navigation back to the holding and switching back to current are not demonstrated end-to-end in this pass.

### Identity source provenance and classification

`resolveIdentityDir` uses `${IIPS_DATA_DIR}/investment/identity`, defaulting to `<server working directory>/.iips-data/investment/identity`. It expects `eligible-roster.json`, `listing-map.json`, `corporate-actions.json`, all `IIPS_INVESTMENT_IDENTITY_V1`. The roster contains issuers and securities, the listing map has entries, and corporate actions have actions; `identity/sources.ts` validates keys, cross-references, effective windows and digests. The IID roadmap designates **operator-maintained** versioned files, not an auto-generated universal feed. No generation failure or wrong target path was proven; the source was absent in the isolated runtime. Real-issuer evidence includes narrow identity input files for individual investigations, not an authorized replacement universe. Test fixtures are explicitly synthetic and were copied only into the temporary test data root. `coverageDependencies` also requires both holdings and watchlist providers: it intentionally refuses partial totals. Name-only and symbol-only issuer inference is not introduced.
