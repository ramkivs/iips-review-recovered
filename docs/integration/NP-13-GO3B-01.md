## 3. PRESERVED NEGATIVE BOUNDARIES

All negative boundaries established by `NP-13-D1-01` (D1-B) and `NP-13-D1-C-01` (D1-C) remain in full force and are preserved unchanged:

1. **Governed-object identity ≠ repository/ref identity.** The governed object is an authoritative logical representation (`NP-13-D1-01 §3.1`, `NP-13-D1-C-01 §2 Semantic 1`) and its identity is distinct from any repository or ref identity.
2. **Evidence-pin identity ≠ governing-object identity.** Recording a commit, tree, blob, or ref as an evidence pin does not make that pin the governed object's identity (`NP-13-D1-C-01 §2 Semantic 4`).
3. **Governance identity ≠ runtime identity.** Governance identity is distinct from runtime realization identity (`NP-13-D1-C-01 §2 Semantic 5`).
4. **Durability destination `IRR @ origin/main` ≠ governed-object identity or binding.** The fact that D0, D1, D1-C, and this G-O-3(b) record are durably published to `ramkivs/iips-review-recovered @ origin/main` is a durability fact only and does not establish `origin/main`, `main`, the current commit, or the current tree as the governed feature baseline's identity or binding (`NP-13-D1-C-01 §5.1`).
5. **No definition by association.** Repository, branch, commit, tree, implementation artifact, runtime realization, and individual workstream record do not define the governed object merely by association (`NP-13-D1-01 §3.1`, `NP-13-D1-C-01 §2 Semantics 2, 3, 6`).

The seven concepts — (1) governed-object identity, (2) evidence/reference identity, (3) durability-record destination, (4) repository, (5) branch/ref, (6) commit/tree, and (7) implementation realization — remain strictly distinct and non-interchangeable.
