## Derived consequences (mechanical, not a decision)
  1. Revoking the sole binding leaves the store file in place with a binding row in REVOKED state.
  2. P-1 can never run again on that store: STORE_ALREADY_EXISTS (file exists) and ALREADY_PROVISIONED
     (a binding/membership row exists in ANY state) both refuse before any SQL.
  3. The partial unique index allows a new ACTIVE row only after the previous ACTIVE row is no longer
     ACTIVE, but no way to insert one exists outside P-1 (which refuses on this store) — a NEW store path
     plus a FRESH one-use PA act would be required.
  4. Re-activating the revoked row (the test fixtures do this) is exactly the 'governed recovery /
     reassignment' action that G2-D5 point (4) reserves to an explicit PA act. None exists.
  => Revoking the sole authoritative binding is one-way under current authority.
