# L-039: subsequent exchange disclosures and the machine-readable zero

## Determination and boundary

**No mapping is authorized on the evidence verified here.** The existing 31 March 2026 KEC consolidated dataset remains `CURRENT_INVESTMENTS = MISSING / NOT_REPORTED`; `L-039` remains **OPEN**. This is a negative mapping determination, not a finding that the exchange filing contains no zero: the audited consolidated NSE XBRL instance contains an actual `in-capmkt:CurrentInvestments = 0`, and the corresponding rendered document displays `Current investments 0.00`. This is material new evidence and must not be suppressed or described as merely a missing caption. A numeric reported zero is distinct from both absence and `NIL_BY_DISCLOSURE` in the existing contract, and, if an authoritative and properly contextualized reported zero is established, can be `PRESENT` and close the bridge without a nil-aggregation policy change.

The earlier runner reports established the instance's filing row and value but did not capture its context. A focused follow-up now verifies the fact, context, dimensions, unit and reported accuracy from the hash-matched original; **source-generation semantics remain unresolved**. See the fact-level follow-up below. The template also renders numerous zero captions absent from the audited PDF; its `NoncurrentInvestments = 0` sits alongside a PDF non-current investment line marked `*` (below rounding norms), not an unambiguously reported numerical zero. These observations raise a genuine ambiguity about the meaning and rounding of the machine zero; they do not prove automatic defaulting, nor do they prove that the issuer did not report zero. The attempt to collect raw context and source semantics via run 42451824428 failed before any job executed (zero jobs); no raw result from that attempt exists. At that stage source bytes were not retained; the follow-up now retains four exact instances/renderings in `source/` as losslessly compressed bytes. Therefore, silently upgrading this specific value to a governed numeric zero, or asserting a definitive issuer nil, would be premature. The uncertainty is an unresolved evidence/adjudication blocker, not proof of absence.

The PDF page 9 extraction places the `*` and the next row's 31.45 / 214.93 on adjacent lines; those numbers are **trade receivables**, not investment values. The 48.73 investment property and 1,422.69 investments are on **standalone** PDF page 20, not the consolidated page. They must not be used to claim the consolidated XBRL contradicts those amounts. The 24 zero elements reported by the template probe are from its own broad "balance-sheet-ish" filter, which also includes cash-flow elements; they are not 24 proven balance-sheet defaults. The iXBRL parser's zero `ix facts` in the runner log is a parser limitation, not evidence that the displayed row is untagged.

## Focused fact-level follow-up — outcome C: indeterminate

The original NSE XML was retrieved again for the specific missing context, matched byte-for-byte against the previously recorded SHA-256, and retained as `source/march-consolidated-xbrl.gz`. Its only occurrence of the concept is the exact raw fact:

```xml
<in-capmkt:CurrentInvestments contextRef="OneI" decimals="-7" unitRef="INR">0</in-capmkt:CurrentInvestments>
```

The QName namespace is `http://www.sebi.gov.in/xbrl/2026-01-31/in-capmkt`. The complete raw referenced context and unit are:

```xml
<xbrli:context id="OneI"><xbrli:entity><xbrli:identifier scheme="http://www.sebi.gov.in/in-capmkt/ScripCode">532714</xbrli:identifier></xbrli:entity><xbrli:period><xbrli:instant>2026-03-31</xbrli:instant></xbrli:period></xbrli:context>
<xbrli:unit id="INR"><xbrli:measure>iso4217:INR</xbrli:measure></xbrli:unit>
```

There is no segment or scenario, hence no explicit or typed dimensions in this context; `xsi:nil` and `precision` are absent. Only one `CurrentInvestments` fact occurs in the instance, so there is no duplicate or conflicting fact of that concept *within this instance*. The identifier 532714 and its scheme are facts of the XML, not an independent corroboration of the BSE listing. The NSE integrated index and rendered filing identify KEC and the filing as consolidated, audited and for 31 March 2026; that classification is not a dimension in `OneI` (the standalone instance also uses `OneI`).

`decimals="-7"` specifies accuracy to 10,000,000 rupees, i.e. one crore; under ordinary XBRL rounding semantics it is not a precision assertion that the underlying economic amount is exactly zero. In the same instance cash is `4112600000` INR at `decimals="-5"` (₹411.26 crore); non-current investments are `0` at `-7`, while the audited PDF marks them `*` below its rounding norms. This is consistent with a rounded zero; it does not establish what the current-investments value actually is, nor establish a template default.

The hash-matched rendered HTML is retained in `source/march-rendered.gz`; it presents `Current investments | 0.00` in **Statement of Asset and Liabilities → Current assets → Current financial asset**, with amounts in lakhs. The inspected row consists of ordinary HTML `th`/`td`, not an inline-XBRL fact element; the corresponding separate XML fact is the source of the QName/context above. No XBRL footnote element was found in the March XML; that does not rule out explanatory information elsewhere. The audited PDF's consolidated page 9 omits the current-investments line, not an express denial of the XML fact. The prior WI-8 annual report PDF p.117 and Note 10 p.129 likewise do not supply an explicit current-investments amount. Neither omission proves that the tagged zero is invalid, nor corroborates its economic meaning.

**Comparative test.** The March standalone instance and the September consolidated instance both contain one `CurrentInvestments = 0`, `decimals=-7`, respectively dated 31 March and 30 September 2026. These are separate filings, not independent proof of how KEC's March consolidated value was generated. No issuer-specific default-generation instruction, contradictory duplicate, or authoritative issuer confirmation was identified. Repetition and the other template rows are consistent with several mechanisms and **do not prove or disprove defaulting**.

**Taxonomy limitation.** The instance's sole schema reference is `in-capmkt-ent-2026-01-31.xsd`; resolving it relative to the instance URL returned HTTP 404 in runner report `runs/fact-context-report.txt`. The applicable taxonomy definition, labels, presentation linkbase and any schema-level default dimensions could not be verified. A publicly available third-party repository contains a 2025 version, not this 2026 entry point, and was not treated as an authoritative replacement. The rendered presentation hierarchy is an observed HTML structure, not a verified taxonomy presentation relationship. Full DTS validation and automatic population semantics are therefore unresolved.

No value is mapped, and `CURRENT_INVESTMENTS` remains `MISSING / NOT_REPORTED`; `L-039` remains **OPEN**. A verified zero is not automatically a nil declaration. Reconsider with the correct taxonomy and authoritative issuer/exchange clarification of rounding and population, or a separately disclosed amount for the same consolidated instant.
